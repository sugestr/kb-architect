# Области, адреса и сводные

Область знания — предмет, набор источников и границы ответственности. Это может
быть человек, компания, кейс или часть жизни. Папка, Git-репозиторий и роль не
обязаны совпадать с областью. Отдельный контур нужен при самостоятельных authority,
доступе, current, жизненном цикле или восстановлении. Обычному досье достаточно
одного понятного входа; паспорт на каждую папку не нужен.

## Один индекс, разные способы чтения

`KNOWLEDGE_INDEX.json` schema 1 сохраняет старые `paths`. Когда этого мало, маршрут
получает `targets`. `id`, `description`, `load_when`, `aliases` остаются общими.
Адреса не содержат копий фактов. Не меняй работающий индекс ради новых полей.

| kind | Поля target | Что читать |
|---|---|---|
| `file` | `path` | файл; эквивалент старого paths |
| `section` | `path`, `section` | раздел по единственному точному Markdown-заголовку |
| `query` | `path`, `command`, `read_only`, `coverage`, `provenance` | tracked рецепт и предметный запрос |
| `project` | `path`, `route`, `relation`, `access`, `scope` | явно названный маршрут другого индекса |

`path` локального target не выходит из корня. У query это адрес рецепта, а не
обязательная копия БД в Git; `command` — массив аргументов, `read_only: true` —
декларация метода, не техническое доказательство безопасности. Resolver команды
не исполняет. Агент проверяет рецепт и использует предметный инструмент в своих
полномочиях. `coverage` описывает охват/исключения, `provenance` — способ получить
источник, дату/ревизию и статус происхождения результата. Для derived БД также
видны источник сборки и freshness; canonical БД имеет собственный backup/recovery.
Нулевая выборка не доказывает полноту загрузки. SQL не преобразуют обратно в Markdown.

`path` project-target — путь к индексу самостоятельного контура, в том числе
`../case/KNOWLEDGE_INDEX.json`. `relation`: `contains`, `references` или
`depends-on`; `access: read-only`; `scope` ограничивает получаемые сведения.
Иерархическое включение не передаёт право правки и не раскрывает всё содержимое.
Оно отличается от наследования профессионального метода роли.

## Единый текущий вход

У каждого проекта один корневой `NOW.md`: актуальные приоритеты, следующие
действия, ожидания и OPEN, дата обновления и ссылки на основания. Подробные
профили, законы, SQL, источники и история остаются в своих слоях. Это общий
интерфейс управления, а не общая схема предметного знания.

`NOW.md` может собираться из принятого ledger/БД: источник, freshness и генератор
указаны явно; производный файл не редактируют параллельно с источником.
`KNOWLEDGE_INDEX.current` адресует только этот файл. Дополнительные знания
загружаются по отдельным маршрутам.

При переходе с `STATUS.md`, `CURRENT.md` или inline-состояния сохрани точный
pre-change commit, перенеси актуальное содержание без утраты уникальных строк,
обнови активные ссылки, генераторы и проверки, затем удали прежний путь. Переезд
завершён без legacy-файла, симлинка или перенаправляющей заглушки; потребители
проверены на новом адресе. История и откат остаются в Git, исторический текст
не переписывается. Существующий `NOW.md` сначала сверяют с прежним каноном.
Инициализатор не выполняет эту миграцию за существующий проект.

Прежние явные current-маршруты продолжают читаться для совместимости, пока проект
не перенесён. Установка patch сама не переписывает проект и не переоткрывает
принятые роли. `kb_index.py <root> --require-now --json` проверяет физический вход,
один current route и отсутствие видимых Git симлинков на него; проверку всех
потребителей он не заменяет. `--current` читает прежние адреса до миграции.
Номер проекта остаётся `7.0.0`.

Пример единого адреса:

```json
{
  "schema": 1,
  "current": "project-current",
  "routes": [{
    "id": "project-current",
    "description": "Current commitments and open questions",
    "load_when": ["orientation or a permitted parent summary"],
    "aliases": ["now", "current"],
    "paths": ["NOW.md"]
  }]
}
```

`kb_index.py <root> --current --json` или `--require <id> --json` возвращает
адреса, их hashes и цепочку переходов. Cycles/неизвестный адрес дают ошибку.
`NOT_READ`/`NOT_RUN` означает, что resolver ещё не прочитал знание и не получил
результат запроса. Указатель не доказывает актуальность факта. Полная валидация
без `--require` проверяет структуру; межпроектное чтение ограничено выбранным
маршрутом. Legacy без current даёт видимый UNKNOWN, а не догадку о NOW.md.

## Сводная для владельца

Сводная соединяет разрешённые current-сигналы и мысли владельца о важности.
Канон задачи/срока/факта остаётся в исходной области; приоритет, скрытие и порядок
на экране принадлежат сводной. «Скрыто» не означает «завершено».
Перечисление прямо прочитанных current-полей со ссылками и оговоркой о freshness
не требует отдельного inference receipt; новый межисточниковый вывод проходит
`retrieval.md`. Мысль владельца о важности остаётся его приоритетом, не новым фактом.

Объяви участвующие области в конфигурации существующего сборщика. Для каждой
получи current по индексу либо явному legacy-адресу. Покажи охват: получено,
устарело, недоступно, адрес не объявлен, исключено владельцем. Необнаруженные
проекты не превращаются в «дел нет». Частичный сбой сохраняет полезные сигналы
остальных областей с отметкой неполноты. Подробность раскрывается по ссылке;
медицинская, финансовая и личная история целиком в общий hub не копируется.

## Вложение, перенос и изменение

Начинай с логической связи. Перемещай физически, только когда это улучшает работу.
До cutover зафиксируй source owner, идентичность объектов, current, историю,
активные ссылки/генераторы и recovery. После переноса проверь те же обычные
вопросы, роли и stops, затем переключи потребителей и удали старый адрес по
правилу завершённого переноса выше. Базовая процедура —
`adopt-existing.md`, перенос между runtime — `move-project.md`.

Исправление источника включает зависимые профили, выводы, расчёты и сводные.
Используй существующие source ids, query lineage и генераторы: пересобери их
либо явно отметь затронутое stale/OPEN. Не вводи универсальный граф зависимостей
ради единичного случая. Новая область не наследует выводы без проверки человека/
объекта, периода, юрисдикции, источника и применимости метода.
