# Базовая дельта для проектов ниже 7.0

Читать только при исходном marker ниже 7.0. После этого — дельта 7.1
и общий цикл `migration.md`. Принятый 7.0 этот файл не перечитывает.

1. Сохрани предметную структуру; текущий вход унифицируй в корневой `NOW.md`.
   Topology focused/portfolio/hybrid описывает границы, не размер. Универсальных
   8 КиБ для project-файла нет. Перенос current — по `knowledge-routing.md`,
   без второй редактируемой копии и без переноса предметных досье ради версии.
2. Объяви способ найти current и нужное знание. Старые paths остаются; targets
   file/section/query/project и current добавляются только использующему их проекту.
   Сводная учитывает участвующие/недоступные области. Логическое вложение не требует
   физического переноса; права и scope дочернего контура сохраняются.
3. Метод остаётся в роли, предметные знания — в KB. При повторяющемся особом методе
   предложи роль/специализацию; не создавать её из-за каждой папки/человека. Extends
   добавляют только при настоящем наследовании. Координатор и специалист различаются.
4. Существенный вывод получает evidence с источником, покрытием, свежестью и
   ограничениями. Принятый SQL/ledger может заменить полный lexical receipt. Для
   lexical fallback использовать новые страницы/оценку; старый итоговый receipt
   не удостоверяет не проверенные им версии и противоречия.
5. Принимающий документы процесс показывает полный объявленный вход, атрибуцию,
   извлечение, слои, OPEN и продолжение после прерывания. Применить это в существующем
   ledger/DB; не строить вторую медицинскую/бухгалтерскую схему. Исправление включает
   зависимые представления либо явную пометку stale.
6. Удалить дубли процедур старой приёмки: текущие project-roles и эта короткая
   application — единственные владельцы. Диагностика read-only, обновление через
   stable updater на безопасной границе. Оценить полезность, ошибки, скорость и
   обслуживание на реальных задачах, прежде чем делать общую раскатку.

Результат пункта может быть «уже выполняется» со ссылкой. Новые schemas, циклы,
поля и роли не обязательны там, где существующий механизм даёт нужный результат.
Для безопасного пилота сначала проверь read-only сценарий или временную копию.
Source/role changes требуют относящейся проверки; универсальный повтор всех
предметных исследований и всей истории миграций не нужен.
